# XZONA Group Bot v7.2 — запуск на Bothost.ru

## 1. Что загружать

Загрузите **содержимое папки проекта**, чтобы в корне Bothost находились:

- `main.py`
- `bot.py`
- `Dockerfile`
- `requirements.txt`
- `app/`

Не создавайте дополнительную папку над `main.py`.

## 2. Настройки проекта Bothost

Рекомендуемый вариант:

- Python/Telegram-проект;
- запуск через собственный `Dockerfile`;
- включён публичный домен;
- приложение запускается командой `python main.py` (Dockerfile уже это делает);
- внешний HTTP-порт вручную не фиксируйте, если Bothost выдаёт `PORT` автоматически.

v7 читает `PORT` автоматически и на этом же порту поднимает `/health` и защищённое окно Telethon.

## 3. Переменные окружения

Обязательно:

```env
BOT_TOKEN=1234567890:AA...
OWNER_ID=123456789
ADMIN_IDS=123456789
DB_PATH=/app/data/bot.db
ANNOUNCE_ON_START=1
TEMP_MESSAGE_TTL=90
```

Для окна Telethon:

```env
TELETHON_WEB_HOST=0.0.0.0
TELETHON_WEB_PUBLIC_URL=https://ВАШ-ДОМЕН-BOTHOST
TELETHON_WEB_TICKET_TTL=900
```

Если Bothost сам передаёт переменную `DOMAIN`, `TELETHON_WEB_PUBLIC_URL` можно не задавать: бот попробует собрать HTTPS URL автоматически. Если ссылка из `/admin → Telethon` открывается не на вашем домене — задайте `TELETHON_WEB_PUBLIC_URL` вручную.

### Постоянная база

`bot.db` содержит игроков, должности, снаряжение, заказы, мероприятия, дипломатию, цели, настройки тем и зашифрованную Telethon StringSession. Поэтому каталог, где лежит БД, **должен быть постоянным между redeploy**.

Если в вашем тарифе/проекте Bothost `/app/data` не является persistent volume, настройте постоянное хранилище средствами панели Bothost и укажите его путь в `DB_PATH`.

## 4. Права Telegram-бота

В основной игровой супергруппе бот должен быть администратором. Нужны:

- чтение сообщений;
- удаление сообщений — для ограничения внешних лидеров/заместителей;
- отправка сообщений;
- желательно закрепление/редактирование своих сообщений.

Если вы используете автоматический перенос новостей/информации из другой группы, добавьте бота и в **исходную** группу, чтобы он получал новые сообщения.

## 5. Первый запуск

После добавления в группу бот сразу публикует сообщение в General/default discussion о том, что система подключена.

Дальше владельцу:

1. Один раз открыть личный чат с ботом и нажать `/start` — только чтобы бот мог прислать защищённую ссылку Telethon.
2. В основной группе: `/admin` → `🔐 Telethon` → `🪟 Открыть окно авторизации`.
3. В браузере: API ID → API HASH → телефон → код Telegram → 2FA (если есть).
4. После подключения Telethon выполнить в основной группе:

```text
/autoconfigure_topics
```

Бот прочитает названия forum topics и попробует автоматически связать:

- General
- Ники игроков
- Снаряжение группировки
- Рынок ГП
- Пункт выдачи заказов
- Снаряжение ГП
- Мероприятия
- Союзы и Война
- Список целей
- Инфа в Зоне (Новости)
- Прочая информация
- Бар «Гильза»

После автонастройки он опубликует **инструкции непосредственно в найденных темах**, поэтому их увидят и участники, которые были в группе до появления бота.

Если название темы отличается, привяжите её вручную соответствующей `/set_..._topic` командой. При ручной привязке инструкция публикуется сразу.

## 6. Повторное оповещение всех

Руководитель может выполнить:

```text
/announce_all
```

Бот повторно отправит актуальные инструкции во все настроенные темы.

При обычном рестарте он не спамит: для каждой версии инструкции помечаются как уже опубликованные.

## 7. Проверка хостинга

Откройте:

```text
https://ВАШ-ДОМЕН/health
```

Ожидается JSON вида:

```json
{"ok": true, "ready": true, "telethon_connected": false}
```

После подключения Telethon `telethon_connected` станет `true`.

Корень домена `/` показывает простую страницу состояния XZONA Group Bot.

## Автоматическая уборка сообщений на Bothost

Временные ответы бота записываются в `bot.db` и удаляются по TTL. Это важно именно для хостинга: если контейнер перезапустился до срабатывания локального таймера, после следующего старта фоновый cleaner удалит просроченные служебные сообщения.

Постоянными остаются только инструкции разделов и итоговые рабочие карточки. Для аварийной ручной уборки временных сообщений руководитель может выполнить `/cleanup_bot_messages`.

Для этой функции `DB_PATH` обязательно должен указывать на persistent storage — иначе после redeploy бот потеряет список сообщений, которые надо дочистить.
