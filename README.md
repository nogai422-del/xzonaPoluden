# XZONA Group Bot v6 — работа внутри тем + окно Telethon

Версия v6 переводит обычную работу бота в **форумные темы игровой Telegram-группы**. Игрокам больше не нужно ходить в личное меню бота для регистрации, склада или заказов.

Личный чат используется только для двух вещей:

1. бот отправляет **владельцу** одноразовую ссылку на браузерное окно авторизации Telethon;
2. при возможности бот отправляет личные уведомления (например, Торговцу).

## Что работает внутри группы

### 🔑 Ники игроков

Участник пишет прямо в настроенной теме двумя строками:

```text
Xan2795
Кладовщик
```

Бот связывает Telegram ID с игровым ником и создаёт запрос на должность. Права включаются только после подтверждения руководством.

Поддерживаемые внутренние должности:

- Лидер
- Заместитель лидера
- Торговец
- Законодатель (Дипломат)
- Кладовщик
- Командир ШО
- Рядовой

Поддерживаются внешние Лидеры и Заместители:

- Наёмников
- Долга
- Монолита
- Греха
- Ренегатов
- Бандитов
- Учёных
- Свободы
- Чистого Неба

После подтверждения внешние представители могут читать все темы, но писать только в General (и в «Ники игроков» для своей карточки). В остальных темах их сообщения автоматически удаляются. Боту для этого нужно право администратора **Удаление сообщений**.

### 🎒 Снаряжение группировки

Вся цепочка идёт в одной теме:

`Принять предмет → игрок → название → количество → комментарий → подтверждение → карточка`

Текстовые ответы администратора (название, количество, комментарий) бот старается удалить после обработки, чтобы тема не засорялась. Итоговая карточка остаётся.

### 🪙 Рынок ГП

Игрок оформляет заказ прямо в теме рынка:

`Новый заказ → предмет → количество → добавить ещё → комментарий → отправить`

Заказ остаётся карточкой в теме. Торговец или руководство меняет статус:

`🟡 Ожидает → 🔵 Принят → 🟣 Собран → ✅ Выдан`

или отклоняет заказ.

Торговца удобнее назначать ответом на его сообщение:

```text
/set_gp_merchant
```

### 🎖 Роли и доступ

В группе:

```text
/admin
```

Далее раздел **Роли и доступ**. Лидер/Заместитель/технический администратор подтверждает запросы на должности. Права проверяются при каждом нажатии кнопки, поэтому старые кнопки не дают доступ после снятия роли.

## Первичная привязка тем

Добавьте бота администратором и выполните команды **внутри нужных тем**:

```text
General:
/set_general_topic

Ники игроков:
/set_nicks_topic

Снаряжение группировки:
/set_storage_topic

Рынок ГП:
/set_market_topic
```

Повторно вывести панели можно командами:

```text
/storage_panel
/market_panel
/nicks_status
/admin
```

## Окно авторизации Telethon

В v6 API HASH, код входа и пароль 2FA **не нужно писать сообщениями боту**.

Бот поднимает маленькую web-страницу. Владелец открывает:

`/admin → 🔐 Telethon → 🪟 Открыть окно авторизации`

После нажатия бот проверяет `OWNER_ID`, создаёт случайную одноразовую ссылку примерно на 15 минут и отправляет её владельцу в личный чат. По ссылке открывается браузерное окно с этапами:

1. API ID
2. API HASH
3. номер телефона
4. код Telegram
5. пароль 2FA, если он включён

После успешного входа Telethon-сессия сохраняется в SQLite в зашифрованном виде. API HASH и StringSession шифруются ключом, производным от `BOT_TOKEN`. Пароль 2FA не сохраняется.

Затем в группе можно нажать **Импортировать старые ники** — Telethon дочитает сообщения темы «Ники игроков», опубликованные до запуска бота.

> Важно: если владелец никогда не открывал личный чат с ботом, Telegram не даст боту отправить ему защищённую ссылку. Один раз нажмите `/start` в личке. Никакого рабочего меню там больше нет.

## Установка

Нужен Python 3.11+.

```bash
python -m venv .venv
```

Windows:

```powershell
.venv\Scripts\activate
```

Linux/macOS:

```bash
source .venv/bin/activate
```

Зависимости:

```bash
pip install -r requirements.txt
```

Создайте `.env` рядом с `bot.py`:

```env
BOT_TOKEN=1234567890:AA...
ADMIN_IDS=123456789
OWNER_ID=123456789
DB_PATH=bot.db

TELETHON_WEB_HOST=127.0.0.1
TELETHON_WEB_PORT=8088
TELETHON_WEB_PUBLIC_URL=http://127.0.0.1:8088
TELETHON_WEB_TICKET_TTL=900
```

Запуск:

```bash
python bot.py
```

## Где брать API ID / API HASH

На аккаунте, который будет использовать Telethon:

1. войдите на `my.telegram.org`;
2. откройте **API development tools**;
3. создайте приложение;
4. получите `api_id` и `api_hash`;
5. вводите их только в браузерном окне v6.

## Если бот запущен на вашем Windows-PC

Настройки по умолчанию подходят:

```env
TELETHON_WEB_HOST=127.0.0.1
TELETHON_WEB_PUBLIC_URL=http://127.0.0.1:8088
```

Окно авторизации открывайте на этом же компьютере.

## Если бот запущен на удалённом сервере

Пример:

```env
TELETHON_WEB_HOST=0.0.0.0
TELETHON_WEB_PORT=8088
TELETHON_WEB_PUBLIC_URL=https://xz-bot.example.com
```

Порт приложения нужно закрыть reverse proxy (Nginx/Caddy) и наружу отдавать **HTTPS**. Не публикуйте порт 8088 без TLS в интернет.

Маршруты web-части:

```text
GET /health
GET /telethon?t=<одноразовый-токен>
```

Страница `/telethon` без действительного одноразового токена возвращает отказ.

## Обновление с v5

Старый `bot.db` можно оставить. v6 использует существующую структуру базы и сохранённую Telethon-сессию. Если Telethon уже был подключён в v5, повторная авторизация не требуется.

Старые личные меню в ранее отправленных сообщениях могут ещё существовать, но новый `/start` направляет пользователей в тематические разделы группы. Основные актуальные сценарии находятся в `app/group_handlers.py`.

## Безопасность

- не публикуйте `BOT_TOKEN`;
- не публикуйте API HASH;
- не пересылайте одноразовую Telethon-ссылку;
- не копируйте файл базы посторонним: в нём находится зашифрованная StringSession;
- `OWNER_ID` должен принадлежать только владельцу;
- для удалённого web-окна используйте HTTPS;
- код Telegram и пароль 2FA вводятся только в браузерной форме и не должны появляться в группе.
