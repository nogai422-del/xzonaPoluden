# XZONA Group Bot v8.0 — Полдень

Общий склад с заявками «участник → Лидер/Заместитель → Кладовщик (Старшина)», общий каталог предметов, доска продаж с обязательной фотографией, таблица отношений между всеми группировками и цели из дипломатии. Враги союзников включаются только подтверждённым Дипломатом.

**Настройка, роли, правила миграции и запуск: [UPDATE_v8_RU.md](UPDATE_v8_RU.md).**

Общему складу соответствует `/set_gp_stock_topic`, личному хранению — `/set_storage_topic`. Если настроен только `storage`, новые складские функции работают там. Существующие привязки и данные сохраняются; перед миграцией создаётся резервная SQLite-копия.

Проверки: `python -m unittest discover -s tests -v`.

Ниже — история предыдущих версий. Описание старого рынка заказов и дипломатии заменено правилами v8.

# XZONA Group Bot v7.6 — ручные разделы + синхронизация участников Telethon

## Главное в v7.6

- Разделы больше **никогда не определяются автоматически**. Руководство само назначает каждую тему командой `/set_..._topic` внутри нужной forum-темы.
- Старые авто-привязки из v7.5 и более ранних версий не считаются подтверждёнными, пока нужный раздел не назначен вручную.
- Если раздел перенесён, бот удаляет свою старую постоянную панель из прежней темы и создаёт/обновляет её только в новой.
- Telethon синхронизирует **реальный состав Telegram-группы**: новые участники, изменившиеся имена/@username и вышедшие.
- Состав Telegram хранится отдельно от игровых профилей: наличие в группе не создаёт фальшивый игровой ник.
- `/admin -> 🔐 Telethon` показывает статус состава и кнопки **👥 Синхронизировать участников** / **📋 Состав группы**.
- Автосинхронизация участников включена раз в час по умолчанию (`TELETHON_MEMBER_SYNC_INTERVAL=3600`). Значение `0` отключает её.

### Ручная привязка разделов

Выполните команды строго внутри соответствующих тем:

```text
/set_general_topic      — General
/set_nicks_topic        — Ники игроков
/set_storage_topic      — Снаряжение группировки
/set_market_topic       — Рынок ГП
/set_delivery_topic     — Пункт выдачи заказов
/set_gp_stock_topic     — Снаряжение ГП
/set_events_topic       — Мероприятия
/set_diplomacy_topic    — Союзы и Война
/set_targets_topic      — Список целей
/set_news_topic         — Инфа в Зоне / Новости
/set_info_topic         — Прочая информация
/set_bar_topic          — Бар «Гильза»
```

Команда `/autoconfigure_topics` оставлена только как заглушка и сообщает, что автоопределение отключено.

### Синхронизация участников

1. Вручную назначьте хотя бы один раздел основной группы.
2. Откройте `/admin -> 🔐 Telethon` и авторизуйте аккаунт.
3. Нажмите **👥 Синхронизировать участников**.
4. Кнопка **📋 Состав группы** покажет зарегистрированных игроков и участников, у которых ещё нет игрового ника.

После этого фоновая синхронизация повторяется с интервалом `TELETHON_MEMBER_SYNC_INTERVAL`.

# XZONA Group Bot v7.4.3 — Bothost /admin hotfix

> v7.4.3 исправляет молчащий `/admin`: в v7.4.2 отсутствовала функция `group_admin_text`, поэтому обработчик падал уже после получения команды. Теперь `/admin` и `/settings` в личке владельца открывают постоянную полную панель. База совместима, `bot.db` удалять не нужно.

v7.4 превращает Telegram-форум игровой группы в набор связанных модулей. Основная работа происходит **внутри тематических разделов группы**, а не в личном меню бота.


## Новое в v7.4 — единая админка и подтверждения должностей

- `/admin` теперь открывает одинаковую полную панель и в игровой группе, и в личке владельца: **Снаряжение**, **Ники**, **Роли**, **Рынок**, **Разделы и запуск**, **Telethon**.
- Когда игрок пишет `Ник + Должность`, в теме «Ники игроков» сразу появляется карточка заявки с кнопками **✅ Подтвердить / ❌ Отклонить** для Лидера/Заместителя.
- После решения игрок получает уведомление прямо в теме с Telegram-упоминанием. Личное сообщение отправляется дополнительно, если игрок ранее открыл бота. Поэтому отсутствие `/start` в личке больше не скрывает решение.
- При ручном назначении должности кнопками админки игрок также получает видимое уведомление в теме «Ники игроков».
- Карточка заявки после обработки превращается в результат и автоматически удаляется через несколько минут, чтобы не засорять тему.
- Исправлены отсутствующие импорты механизма автоочистки в group-first обработчиках.

## Новое в v7.3 — удобное назначение должностей

После импорта старых ников больше не нужно искать сообщения игроков и писать `/set_role` вручную.

Откройте:

```text
/admin → 🎖 Роли и доступ
```

Там доступны кнопки:

- **👤 Без должности** — все импортированные/зарегистрированные игроки без подтверждённой должности;
- **👥 Все игроки** — полный список с пагинацией;
- **⏳ Заявки** — новые заявки игроков;
- **🔎 Найти игрока** — поиск по нику, @username, имени или Telegram ID.

После выбора игрока должность назначается одной кнопкой. Для внешнего представителя сначала выбирается группировка, затем «Лидер» или «Заместитель». Должность можно снять из той же карточки.

### Ограничения должностей

- **Лидер** — максимум 1 человек;
- **Заместитель лидера** — максимум 5 человек;
- **Торговец, Законодатель (Дипломат), Кладовщик, Командир ШО, Рядовой** — без ограничения количества.

Ограничения проверяются не только интерфейсом, но и базой: второй Лидер или шестой Заместитель не назначится даже через старую команду `/set_role` или подтверждение старой заявки.

В постоянной инструкции темы **«Ники игроков»** бот показывает только доступные должности. Если Лидер уже назначен, «Лидер» исчезает из списка. Для Заместителя показывается остаток мест, например `свободно 2/5`; при заполнении всех пяти строка исчезает. После назначения или снятия роли эта инструкция обновляется на месте, без создания нового сообщения.

## Что реализовано

### 🔑 Ники игроков / роли

Участник пишет в теме две строки:

```text
Xan2795
Кладовщик
```

Поддерживаются внутренние должности:

- Лидер
- Заместитель лидера
- Торговец
- Законодатель (Дипломат)
- Кладовщик
- Командир ШО
- Рядовой

И Лидеры/Заместители внешних группировок: Наёмники, Долг, Монолит, Грех, Ренегаты, Бандиты, Учёные, Свобода, Чистое Небо.

Должность вступает в силу только после подтверждения через `/admin → Роли и доступ`.

Внешние лидеры/заместители читают все темы, но писать могут только в General (и свою регистрационную карточку в «Ники игроков»). В остальных рабочих темах их сообщения удаляются.

### 🎒 Снаряжение группировки

Кладовщик/руководство:

`Принять → игрок → предмет → количество → комментарий → карточка → Выдать`.

Есть активное хранилище, история выдач и привязка к профилям игроков.

### 🪙 Рынок ГП

Игрок формирует заказ прямо в теме:

`предмет → количество → ещё позиции → комментарий → отправить`.

Статусы:

`🟡 Ожидает → 🔵 Принят → 🟣 Собран → ✅ Выдан` либо `❌ Отклонён`.

Торговец назначается ответом `/set_gp_merchant` на его сообщение.

### ⚛️ Пункт выдачи заказов

Когда Торговец отмечает заказ как **собранный**, бот автоматически создаёт карточку в теме Пункта выдачи. Кнопка `✅ Выдан игроку` закрывает заказ и обновляет исходную карточку Рынка ГП.

### 🪖 Снаряжение ГП

Торговец/руководство ведёт остатки предметов. При принятии/выдаче заказа бот проверяет наличие. Если всего достаточно — при выдаче остатки уменьшаются автоматически. Если нет — Торговец получает предупреждение и может скорректировать склад вручную.

### 🎮 Мероприятия

Командир ШО/руководство создаёт мероприятие:

- название;
- дата/время;
- лимит участников;
- описание.

Участники нажимают `✅ Участвую`, могут отменить участие. Карточка обновляет счётчик и список участников. Руководство закрывает запись или завершает мероприятие.

### 🤝 Союзы и Война

Дипломат/руководство ведёт отношения с группировками:

- 🟢 Союз
- ⚪ Нейтралитет
- 🔴 Война

Сохраняется комментарий/причина и запись в журнале действий.

### 🏴 Список целей

Командир ШО/руководство создаёт цель с:

- ником/названием;
- причиной;
- наградой;
- последним местоположением.

Статусы: активна → в работе → выполнена / отменена.

### 📈 Инфа в Зоне (Новости)

Редакторы с `news.manage` публикуют записи вручную. Также можно открыть **исходную тему** в другой группе и выполнить:

```text
/set_news_source
```

После этого новые сообщения из неё копируются в настроенную тему Новостей. Бот должен быть участником исходной группы.

### 🗺 Прочая информация

Работает аналогично новостям: ручные записи + источник из другой темы/группы:

```text
/set_info_source
```

### 🍻 Бар «Гильза»

Свободное общение. Бот публикует только стартовую инструкцию и не превращает этот раздел в служебный.

## Видимое включение бота для уже существующих участников

Это предусмотрено отдельно:

1. При добавлении бота в группу он публикует первое сообщение о запуске системы.
2. При ручной привязке каждой темы бот публикует **инструкцию прямо внутри неё**.
3. На последующих рестартах инструкции не спамятся: хранится отметка версии объявления.
4. Руководитель всегда может повторить их командой `/announce_all`.

Если v7 запускается поверх уже настроенной базы v6, при первом старте он автоматически отправит новые v7-инструкции в сохранённые темы.

## Автоочистка служебных сообщений

Чтобы бот не засорял темы, v7.4 разделяет сообщения на два типа:

- **постоянные** — одна инструкция/панель на тему и итоговые карточки (заказ, мероприятие, цель, имущество);
- **временные** — подсказки, ошибки, списки, промежуточные меню, ответы на команды. Они автоматически удаляются.

По умолчанию временные сообщения живут около 90 секунд (`TEMP_MESSAGE_TTL=90`). Команды настройки удаляются почти сразу после выполнения. Текст, который пользователь вводит в пошаговых сценариях (название предмета, количество, комментарий), бот также удаляет после сохранения, если у него есть право **Удаление сообщений**.

Удаление устойчиво к рестартам Bothost: ID временных сообщений сохраняются в SQLite, а фоновая уборка после redeploy дочищает просроченные записи. Поэтому перезапуск контейнера не должен оставлять старые служебные сообщения навсегда.

Если понадобится ручная уборка всех отслеживаемых временных сообщений:

```text
/cleanup_bot_messages
```

Команда не затрагивает постоянные инструкции и рабочие карточки.

## Telethon — отдельное окно авторизации

`/admin → 🔐 Telethon → 🪟 Открыть окно авторизации`.

Владелец получает в личку одноразовую ссылку. В браузере вводятся API ID, API HASH, телефон, код Telegram и 2FA. Пароль 2FA не сохраняется. API HASH и StringSession хранятся в БД в зашифрованном виде.

Telethon используется для:

- импорта старых ников;
- синхронизации текущего состава основной группы.

## Привязка тем вручную

Старые команды:

```text
/set_general_topic
/set_nicks_topic
/set_storage_topic
/set_market_topic
```

Новые:

```text
/set_delivery_topic
/set_gp_stock_topic
/set_events_topic
/set_diplomacy_topic
/set_targets_topic
/set_news_topic
/set_info_topic
/set_bar_topic
```

Команду нужно отправить **внутри нужной темы**.

## Автонастройка тем

Автоопределение разделов отключено. Все темы назначаются только вручную.

## Администрирование

```text
/admin
```

Содержит роли, хранилище, рынок, Telethon и раздел `🧩 Разделы и запуск` с состоянием всех модулей и журналом действий.

Дополнительно:

```text
/announce_all       — повторно показать инструкции во всех темах
/my_role            — мой ник и должность
/set_role ...       — назначить должность ответом на сообщение
/clear_role         — снять должность ответом на сообщение
```

## Bothost.ru

Подробная инструкция находится в `BOTHOST_START_RU.md`.

Основное:

- используется `Dockerfile`;
- v7 автоматически использует `PORT`, выдаваемый хостингом;
- `/health` доступен на публичном домене;
- `DB_PATH` должен указывать на постоянное хранилище;
- для браузерной авторизации Telethon нужен HTTPS URL Bothost.

## Важное по Telegram

Боту нужны права администратора, особенно **Удаление сообщений**. Для зеркалирования из другой группы бот должен находиться и в исходной группе.
