# Полдень: обновление v8.1

## Вход Telethon по QR-коду

Откройте `/admin → Telethon → Открыть окно авторизации`. Перейдите по личной ссылке, введите API ID и API HASH, нажмите **Войти по QR-коду**. Номер телефона и код сообщения для этого способа не нужны.

На телефоне: **Telegram → Настройки → Устройства → Подключить устройство**. Отсканируйте QR с экрана компьютера и подтвердите вход. Если включён облачный пароль, страница автоматически предложит 2FA. Истёкший QR можно обновить кнопкой. Вход по номеру телефона сохранён.

После обновления установите зависимости `pip install -r requirements.txt` или пересоберите Docker-контейнер и перезапустите бот. Добавлена библиотека `qrcode`. QR создаётся самим ботом, без сторонних сервисов. Сессия сохраняется в зашифрованном виде.

Изменения внесены в исходный проект. Для появления функций в Telegram обновите запущенную копию бота и перезапустите её. В этой работе бот не подключался к Telegram: проверки выполнены на временных базах и имитации Telegram API.

## Подключение к темам

Ручные привязки сохраняются. Для структуры вашего чата используйте команды внутри соответствующих тем:

| Тема | Команда |
|---|---|
| Снаряжение группировки — общий склад | `/set_gp_stock_topic` |
| Личное снаряжение — вещи игроков | `/set_storage_topic` |
| Рынок ГП — объявления участников | `/set_market_topic` |
| Торговец Локи / Локки — заказы товаров | `/set_trader_topic` |
| Дипломатия | `/set_diplomacy_topic` |
| Список целей | `/set_targets_topic` |
| Готовые заказы — уведомления Локи | `/set_ready_orders_topic` |

Назначайте темы от имени Лидера, Заместителя или технического администратора. Команды связывают существующие темы с модулями. После настройки выполните `/announce_all`. При `ANNOUNCE_ON_START=1` постоянные инструкции также обновляются при первом запуске v8.

Общий склад использует `gp_stock`. Если эта тема не настроена, новые функции склада работают в `storage`. Если обе привязки ведут в разные темы, личное хранение остаётся отдельно.

В `/admin → Роли и доступ` подтвердите должности:

- **Лидер / Заместитель** — одобрение и отклонение заявок.
- **Кладовщик (Старшина)** — каталог, остатки и фактическая выдача.
- **Законодатель (Дипломат)** — отношения и решения по врагам союзников.
- Остальные участники — внутренние должности для подачи заявок и объявлений.

«Старшина» принимается при регистрации так же, как «Кладовщик». Назначенные ранее Кладовщики сохраняют права. Выдача требует подтверждённой должности Кладовщика. Включение врага союзника требует подтверждённой должности Дипломата: Лидер, Заместитель и технический администратор не заменяют его в этом решении.

## Склад

**Остатки / заявка → предмет → количество → причина → проверка → отправка.**

1. Заявка появляется в складской теме с упоминаниями Лидера и Заместителей.
2. Руководитель одобряет или отклоняет её. Одобрение резервирует количество. Если другой заявке уже достался остаток, одобрение не проходит.
3. После одобрения появляется карточка выдачи с упоминанием Кладовщиков.
4. После передачи предмета Кладовщик нажимает **Подтвердить выдачу**. Уменьшаются общий остаток и резерв. Повторное нажатие не списывает имущество ещё раз.

Уведомления приходят в тему группы; личная переписка с ботом не требуется. Если ответственные должности не назначены, карточка сообщает об этом. Очередь доступна руководству и Кладовщику. Игрок видит свои заявки, включая завершённые. История хранит принявшего решение и выдавшего имущество.

Заявитель или руководство могут отменить незавершённую заявку. Если она одобрена, резерв освобождается. После выдачи отмена недоступна.

В **Управлении складом** доступны добавление предмета, изменение общего количества, переименование, удаление из активного списка и восстановление. Общее количество включает резерв; уменьшать его ниже резерва нельзя. Удаление возможно после обнуления остатка и завершения заявок. История и объявления сохраняются.

Каталог общий для склада, рынка, старого учёта вещей и заказов. Он учитывает регистр, лишние пробелы и «ё/е». Переименование обновляет связанные позиции. Есть поиск и страницы по восемь предметов. Новое название из объявления запоминается, но не добавляет имущество на склад.

Старые вещи, принятые от игроков, не переводятся в собственность группировки автоматически. Они остаются в личном хранении. Общий склад использует прежние остатки `gp_stock`.

## Рынок — доска объявлений

**Создать объявление → предмет → фотография → цена → описание → предпросмотр → Опубликовать.**

- Предмет выбирается из каталога или добавляется новым названием.
- Обязательна одна фотография, отправленная как фото. Файл, текст без фото и альбом не принимаются.
- Цена — целое число в игровых рублях от 1 до 1 000 000 000 000.
- Описание — до 600 символов; название — до 80.
- Карточка содержит фото, название, цену, описание и ссылку на продавца.
- Продавец может отметить **Продано** или **Снять**. Руководство и Торговец могут закрывать объявления как модераторы.
- Закрытая карточка остаётся в теме с новым статусом и исчезает из активных продаж.

Принятые сообщения ввода удаляются при наличии у бота такого права. Подсказки и предпросмотр очищаются через десять минут. Отмена — кнопкой или `/cancel`. Незавершённые формы хранятся в памяти: после перезапуска их нужно заполнить заново. Каталог, отправленные объявления и заявки сохраняются в SQLite.

Заказы торговцу оформляются отдельно в теме «Торговец Локи»: **Новый заказ → название → количество → дополнительные позиции/комментарий → отправить**. Получатель назначается командой `/set_gp_merchant` в ответ на сообщение торговца либо `/set_gp_merchant @username`. В заказе до 20 позиций. Есть «Мои заказы» и очередь торговца.

Локи отмечает заказ принятым, затем собранным. После кнопки **Заказ собран** бот отправляет в **Готовые заказы** карточку с именем торговца, составом заказа и упоминанием покупателя. После получения торговец нажимает **Выдан игроку**. При сбое доставки уведомление повторяется автоматически. Уже отправленные карточки сохраняются и повторно не создаются при обычном перезапуске.

Новые заказы Локи не используют остатки склада группировки. Старые заказы сохраняют свои прежние резервы и правила списания. Объявления Рынка ГП также не списывают имущество. Рынок ГП и Торговец Локи назначаются в разные темы.

## Дипломатия и цели

**Таблица отношений** отправляет изображение в стиле КПК. Группировки расположены по строкам и столбцам; номер столбца соответствует номеру строки. Зелёный «+» — союз, жёлтый «=» — нейтралитет, красный «×» — война, серый «?» — нет данных. Бот не назначает отношения из сюжета S.T.A.L.K.E.R.: используются ваши игровые данные.

**Изменить отношения → первая группировка → вторая группировка → статус.** Отношения симметричны. Их меняют Дипломат и руководство. Можно добавить новую группировку; поддерживается до 30. Старые отношения «Полдень ↔ другая группировка» импортируются.

- Война с Полднем автоматически создаёт цель-группировку.
- Враг союзника появляется во **Врагах союзников**, но ещё не становится целью.
- Только подтверждённый Дипломат может нажать **Включить** или **Не включать / снять**.
- Прекращение войны с Полднем снимает прямую цель. Изменение союза или войны, на которых основано решение Дипломата, аннулирует это решение.
- Новая война после мира требует нового решения. Старые кнопки с прежним основанием отклоняются.
- Полдень и текущие союзники не становятся кандидатами из-за конфликтов между союзниками. Враждебность не распространяется по цепочкам.
- Цели-группировки управляются дипломатией. Обычные цели на игроков и их история сохраняются отдельно.

В теме целей бот поддерживает актуальный список группировок. Изменения отношений и решения записываются в журнал. Для свежего изображения нажмите **Таблица отношений** повторно.

## Обновление запущенного бота

### Bothost / Docker

1. Загрузите обновлённые файлы или архив поставки. Сохраните прежние переменные окружения и постоянный каталог `/app/data`.
2. Пересоберите контейнер из `Dockerfile`: добавлены Pillow и шрифт DejaVu для кириллицы.
3. Перезапустите бот. Миграция выполняется автоматически. Перед первым обновлением существующей базы создаётся согласованная SQLite-копия `bot.db.pre-v8.bak` рядом с оригиналом. База не удаляется.
4. Проверьте привязки и должности. Оформите пробную заявку, проведите одобрение и выдачу, затем опубликуйте тестовое объявление.

### Локальный запуск — PowerShell, Python 3.10+

```powershell
Set-Location 'C:\Users\Necrpnomicon\Desktop\ScriptsPy\GitHub\xzonaPoluden'
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
# Сохраните BOT_TOKEN и корректный DB_PATH в существующем .env.
.\.venv\Scripts\python.exe main.py
```

Запускайте одну копию бота. `.env`, базы и токены не включены в архив поставки.

Карточки проверяются каждые 15 секунд. Ошибки связи повторно обрабатываются; сохранённые решения не теряются. После обычного перезапуска опубликованные карточки обновляются на месте. Если Telegram принял сообщение, но ответ боту потерялся при обрыве связи, возможна повторная карточка; это не создаёт повторной заявки или списания.

Для работы нужны права отправлять сообщения и фотографии в темы. Для очистки ввода — удалять сообщения. Если бот не получает текстовые шаги, назначьте его администратором группы или проверьте privacy mode в BotFather.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Проверяются миграция старой схемы, резервы, параллельные одобрения/выдачи/отмена, роли, каталог, фото и предпросмотр, темы, повторные нажатия, дипломатические правила, повторная публикация после сбоя и обновление карточек.
